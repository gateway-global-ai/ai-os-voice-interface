# AMD-2026-009 — Intent-Scoped Web Retrieval and Governed Website Review

## 0. Status and intent

| Field | Value |
|-------|--------|
| **Status** | `draft` — **outline for Council / architecture review** before normative merge into specs and product code |
| **Framing** | This is **not** “add a search box.” It formalizes **governed external knowledge acquisition**: **bounded retrieval** under explicit **search scope**, optional **structured review** of returned evidence, and **auditability** — aligned with **AIOS-SPEC-009** execution boundaries and **AIOS-SPEC-007** integration discipline. |

**Relationship to implementation:** Today, **Programmable Search Engine (PSE)** configuration (sites, `cx`, API key on the MCP host) is an **operator** concern. This amendment **raises** that model to **policy**: which intents may trigger which **retrieval modes**, what **evidence** may enter interpretation, and what **outputs** count as governed artifacts.

---

## 1. Purpose

1. Introduce a **normative execution pattern** for web-sourced knowledge that sits **between** raw “search the internet” and **Workspace**-bound tools:

   ```text
   intent resolution
     → search scope class (policy)
     → bounded web retrieval (PSE / Custom Search JSON API or successor)
     → optional governed website review / extraction (structured skill outputs)
     → skill selection / action proposal (existing plan & scope layers)
     → outcome + audit
   ```

2. Ensure **retrieval boundaries**, **interpretation of external sources**, **evidence handling**, **token economics**, and **escalation** are **explicit** — not emergent from ad hoc prompts.

3. Prevent default **unbounded** public-web research: broad or expensive modes **SHALL** be **non-default** and **policy-gated** where this amendment is ratified.

4. **No parallel bounding system:** Web retrieval and website review **SHALL** execute **within** a valid **Execution Scope Envelope** (**AIOS-SPEC-010**). Retrieval and review **SHALL NOT** introduce ad hoc limits that bypass **scope** validation — see §1.1 and §6.

### 1.1 Binding to Execution Scope Envelope (AIOS-SPEC-010)

1. **Web retrieval** and **governed website review** **SHALL** be carried out only when an **approved** **Execution Scope Envelope** is in force for the step (same control plane pattern as other governed reads).
2. **Logical resource keys** for external knowledge (e.g. virtual paths for “this PSE query window” or “this result-set review”) **SHALL** appear in **`review_files`** (or as **SPEC-010** defines for read surfaces) so that **no review** occurs **outside** the envelope’s declared scope.
3. **MUST NOT:** Treat “search scope class” in §4 as a **second** authority that overrides **SPEC-010**; the two **SHALL** be **consistent** — policy selects **search scope class**, **SPEC-010** records **what** may be read and reviewed for that execution.

---

## 2. Scope

**In scope**

- **Search scope classes** (taxonomy) and mapping to **intent** or **plan** stages.
- **Governed skills** (conceptual IDs) for **review** and **structured extraction** from **in-scope** returned pages or snippets only.
- **Source boundedness** rules (no silent link-chasing unless explicitly allowed).
- **Outcome contract** for website review (structured fields, not prose-only).
- **Cost / token policy** tiers for retrieval + review.
- **Audit record** minimum: scope used, engine/config reference, domains or patterns, result identifiers reviewed; **correlation** to intent and plan execution identifiers (**§9**).
- **AIOS-SPEC-010** alignment: envelope-backed retrieval and review (**§1.1**, **§6**).

**Out of scope (this amendment)**

- Replacing **AIOS-SPEC-007** Workspace intents; **workspace.web.search** remains the **Phase 1** MCP bridge unless a later spec renames or splits it.
- Vendor MCP implementation details beyond **declaring** that **GOOGLE_PSE_*** (or equivalent) **SHALL** be **server-side** and **out of browser bundles**.
- Full UI design (primary vs operator) — **AMD-2026-007** remains authoritative for surface split; this amendment **adds** evidence types.

---

## 3. Definitions

| Term | Definition |
|------|------------|
| **Web retrieval** | A **bounded** call chain that returns **search results** (snippets, titles, links) from an **approved** Programmable Search Engine or equivalent, under **AIOS-SPEC-009** execution mode and policy. |
| **Search scope class** | A **labeled** retrieval posture (examples in §4) that determines **which sites or patterns** the engine may query and **which intents** may use it. |
| **Website review (governed)** | A **post-retrieval** step that **MAY** run only on **evidence inside the retrieval result set** (snippets + explicitly allowlisted fetch rules if any), producing a **structured** artifact per §7. |
| **External knowledge acquisition** | The **combined** pattern: retrieval + optional review + **registered** audit fields — **not** casual browsing. |

---

## 4. Search scope classes (normative taxonomy — draft)

These **SHALL** be registered in the policy / capability index upon ratification. Implementations **MAY** start with a subset.

| Class ID (illustrative) | Description | Typical PSE posture |
|---------------------------|-------------|---------------------|
| `web.search.approved_domains` | Only domains on an **allowlist** (e.g. vendor docs, internal mirrors). | Dedicated engine or strict site list. |
| `web.search.governance_corpus` | Curated **governance** or **spec** hosts. | Engine scoped to `governing_docs` hosts + mirrors. |
| `web.search.reference_public` | **Narrow** public reference (e.g. encyclopedia, standards bodies). | Single-site or small pattern list (e.g. Wikipedia-only). |
| `web.search.broad_public` | **Higher-risk**, higher-cost; **non-default**. | Requires **explicit** policy; may remain **disabled** in many tenants. **Trigger (normative):** use of this class **SHALL** require **at least one** of: (a) **explicit intent classification** to a **pre-registered** intent or plan template that lists `web.search.broad_public`; (b) **user or operator confirmation** recorded in the audit chain; (c) a **policy-defined escalation rule** (e.g. operator-only, break-glass). **SHALL NOT** be the silent default for generic queries. |

**Note:** Google’s deprecation of “search the entire web” on new PSEs **reinforces** this model: **scope is expressed by site/pattern lists**, not by a single unconstrained engine.

## 5. Governed skills (conceptual — to be bound to capability IDs at ratification)

| Skill (conceptual) | Role |
|---------------------|------|
| `web.review.result_set` | Map a **bounded** result list to **relevance**, **intent alignment**, and **next-step** hints (structured). |
| `web.review.page` | Where policy allows **single-page** follow-up, review **one** URL from the result set (no arbitrary graph expansion). |
| `web.extract.intent_signals` | Emit **fields** (e.g. suggested skill id, confidence, citations) — **not** free-form only. |

Exact **capability strings** and **router** wiring are **deferred** to implementation specs after this amendment is approved in outline.

### 5.1 Review modes (normative)

| Mode | LLM review | Behavior |
|------|------------|----------|
| **snippet_only** | No | Retrieval results (snippets/titles/links) **only**; no post-retrieval review step. Default for lowest cost and highest safety where policy allows. |
| **result_set_review** | Yes | Structured mapping over the **bounded** result list (**§7**); **no** extra page fetch unless policy escalates to **page_review**. |
| **page_review** | Yes | **Single** URL **from the result set** may be fetched and reviewed per **§6** when policy allows; **not** multi-page browsing. |

**When review is required vs optional:** Policy **SHALL** declare which **search scope classes** and **intents** require **result_set_review** or **page_review** vs **snippet_only**. Where unspecified, implementations **SHALL** default to **snippet_only** for automated downstream execution.

---

## 6. Source boundedness

1. **SPEC-010 alignment:** No retrieval or review step **SHALL** execute **outside** the **Execution Scope Envelope** in force for that operation (**§1.1**). **Review** **SHALL** apply only to evidence that **falls within** declared **review_files** (or equivalent **SPEC-010** read surface) for that step.
2. **Default:** The model **SHALL** consume only **retrieval outputs** (snippets, titles, links) returned in the **same** governed call unless **policy** allows **fetch** of specific URLs (**page_review** mode).
3. **MUST NOT:** Automatic **recursive** crawling, **unbounded** link following, or **arbitrary** “open URL” without scope class + audit + valid envelope.
4. **MAY:** **Escalation** to a **broader** scope class only via **explicit** plan step + policy (and **cost** tier), logged per §9.

---

## 7. Outcome contract (website review)

Structured outputs **SHALL** include where review runs (minimum draft):

| Field | Purpose |
|-------|--------|
| `page_summary` | Short neutral summary tied to **provided** evidence. |
| `relevance_to_intent` | Enum or score + rationale. |
| `suggested_skill` | Optional capability id for downstream plan. |
| `suggested_action` | Optional proposal id (non-executing until gated). |
| `confidence` | Bounded (e.g. low / medium / high) with **caveats**. |
| `source_refs` | Stable refs to **search result indices** or **URLs** as returned (not invented). |

Prose-only answers **SHALL NOT** satisfy **governed** website review for **automated** downstream execution without human or operator acceptance where policy requires.

### 7.1 Failure and low-confidence behavior

1. **Structured output failure:** If a **governed** review step **cannot** produce a **valid** structured artifact matching **§7** (schema violation, tool failure, refusal), the system **SHALL** treat the outcome as **non-executable** for automated downstream actions: **no** silent promotion to plan execution.
2. **Low confidence:** If **`confidence`** is below policy thresholds (or **relevance_to_intent** indicates **low** alignment), the system **SHALL** **require** **user** or **operator** acknowledgment before any **write**, **send**, or **irreversible** action — or **SHALL** return a **deferred** outcome with visible rationale.
3. **Fallback:** The system **MAY** fall back to **snippet_only** presentation and **SHALL** record the fallback in audit (**§9**).

---

## 8. Cost and token policy

1. **Broad** or **multi-step** web review **SHALL** be treated as a **higher-cost retrieval mode** — **not** the default for every intent.
2. **Token budgets** for review **SHALL** be **configurable** per scope class and **surface** (primary vs operator).
3. **Fallback:** On budget exceed, **SHALL** degrade to **snippet-only** or **defer** with user-visible reason — **not** silent remote expansion.

---

## 9. Auditability

Minimum audit record for a **web retrieval + review** chain **SHALL** include:

- **Originating intent** identifier and **search scope class** used.
- **Linkage to execution graph (AIOS-SPEC-009):** **plan_id** (or equivalent plan instance id), **execution** / **step** correlation as defined by the product audit model (e.g. `execution_id`, `auditId` from the control plane) — **SHALL** be joinable so operators can trace **retrieval → review → proposal** in one chain.
- **Engine / configuration reference** (e.g. PSE `cx` id or policy alias — **not** raw API keys).
- **Query** (or hashed where required by policy).
- **Domains or patterns** applicable to that engine.
- **Result set identifiers** reviewed (indices, URLs as returned).
- **Review mode** (**§5.1**) and **Review artifact** id or hash if structured output is persisted.
- Where **`web.search.broad_public`** was used, evidence of **which** trigger from §4 applied: (a), (b), or (c).

## 11. Non-goals (explicit)

This amendment **MUST NOT** be read as authorizing:

- **“AI can browse anything.”**
- **“Search everything, then summarize”** as a **default** product behavior.
- **Unaudited** use of external web content as **ground truth** for **high-stakes** actions without human or policy gates.
